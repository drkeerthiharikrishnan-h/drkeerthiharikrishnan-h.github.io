Submission tooling: CDISC standards and open-source R packages

The standards a sponsor's study data are expected to follow when sent to FDA or PMDA (SDTM, ADaM, Define-XML, Dataset-JSON) and the open-source tooling around them: the CDISC rules engine for validation, pharmaverse packages that build SDTM and ADaM datasets and write transport files, public test data, and the R Consortium pilots that sent R-based packages to FDA. Scope words such as "required by FDA and PMDA" are CDISC's own. Each entry is described from the page opened on 12 Nov 2026.

Each entry is written from the page named as its source, opened on the date shown. A vendor's statement about its own product is tagged vendor-published; open-source projects, standards bodies and public agencies are tagged publisher-published. Nothing proprietary was run: an entry that is not executable here says "documented, not executed here".

Define-XML

CDISC · Publisher-published · documented, not executed here

Standard that carries the metadata describing tabular datasets: human and animal study datasets in SDTM or SEND and analysis datasets in ADaM. CDISC states that Define-XML is required by the US FDA and the Japanese PMDA for every study in each electronic submission, with FDA details in the FDA Data Standards Catalog for NDA, ANDA and certain BLA submissions.

A data standard, not software; documented, not executed here. Tools that write it include the pharmaverse packages on this page; the Pinnacle 21 entry is not cited (see not_cited).

Source: Define-XML | CDISC, CDISC. Opened 12 Nov 2026.

SDTM and ADaM

CDISC · Publisher-published · documented, not executed here

SDTM is a standard for organising and formatting collected study data; CDISC notes it is also used for non-clinical data (SEND), medical devices and pharmacogenomics studies. ADaM defines dataset and metadata standards for analysis datasets, with traceability between analysis results, analysis data and SDTM data. CDISC states each is one of the required standards for data submission to FDA (U.S.) and PMDA (Japan).

A data standard, not software; documented, not executed here. Open-source R packages that build SDTM and ADaM datasets are listed below (sdtm.oak, admiral).

Source: SDTM | CDISC, CDISC. Opened 12 Nov 2026. Also opened: CDISC ADaM standard page.

Dataset-JSON

CDISC · Publisher-published · open to run here

Exchange standard for sharing tabular data in JSON, designed for scenarios including regulatory submissions and API-based exchange. Each dataset can optionally reference a Define-XML document. The CDISC page lists Dataset-JSON v1.1 dated 5 December 2024 and v1.0 dated 23 August 2023. The GitHub repository holds the specification, LinkML and JSON schemas, and SDTM, ADaM and SEND examples in JSON, NDJSON and compressed form.

The standard itself is documentation; what runs locally is the open-source tooling. The schema and examples repository shows an MIT licence; the datasetjson R package on CRAN (0.4.1, published 2026-10-22) is under Apache License (>= 2) and reads, writes and validates Dataset-JSON files. Not installed or run here.

Source: Dataset-JSON | CDISC, CDISC. Opened 12 Nov 2026. Also opened: Dataset-JSON schema, specification and examples; MIT, CRAN page for the datasetjson R package.

CDISC Rules Engine (CORE), open source

CDISC · Publisher-published · open to run here

Open-source offering of the CDISC Rules Engine, a tool for validating clinical trial data against data standards; it can be downloaded as an executable or run from source. The README says rule validation is at present split across two engines: for SDTM or FDA Business Rules use the refactored SQL engine (a separate repository), and for TIG, USDM or SEND use the CDISC engine in this repository.

MIT per the repository. Read the "Which Engine Should I Use?" section before choosing. Not installed or run here.

Source: GitHub - cdisc-org/cdisc-rules-engine: Open source offering of the cdisc rules engine, CDISC (cdisc-org/cdisc-rules-engine GitHub repository). Opened 12 Nov 2026.

admiral

pharmaverse · Publisher-published · open to run here

ADaM in R Asset Library: an open-source, modular toolbox for programming CDISC-compliant ADaM datasets in R. The CRAN description states that ADaM datasets are a mandatory part of any New Drug or Biologics License Application submitted to the US FDA.

Apache-2.0 per the repository; CRAN lists admiral 1.5.0 (published 2026-06-12, Apache License (>= 2), R >= 4.1). Not installed or run here.

Source: GitHub - pharmaverse/admiral: ADaM in R Asset Library, pharmaverse (pharmaverse/admiral GitHub repository). Opened 12 Nov 2026. Also opened: CRAN page for admiral.

pharmaversesdtm and pharmaverseadam (test data packages)

pharmaverse · Publisher-published · open to run here

Test data packages for the pharmaverse family. pharmaversesdtm provides SDTM test datasets, both therapeutic-area agnostic (DM, VS, EG and others) and therapeutic-area specific (RS, TR, OE and others). pharmaverseadam provides ADaM datasets built from those SDTM datasets with the admiral template scripts.

Apache-2.0 per the repository; both packages are on CRAN (pharmaverseadam 1.4.0, published 2026-10-14, Apache License (>= 2)). These are test datasets, not trial data. Not installed or run here.

Source: GitHub - pharmaverse/pharmaversesdtm: Test SDTM data for use within the pharmaverse family of packages, pharmaverse (pharmaverse/pharmaversesdtm GitHub repository). Opened 12 Nov 2026. Also opened: CRAN page for pharmaverseadam.

xportr

Atorus Research (atorus-research on GitHub) · Publisher-published · open to run here

R package that attaches metadata to a local data frame, runs dataset-level validation checks and writes SAS transport v5 (xpt) files, so that ADaM or SDTM xpt files are ready for a dataset validator or a regulatory agency.

MIT per the repository; the README installs it from CRAN. Not installed or run here.

Source: GitHub - atorus-research/xportr: Tools to build CDISC compliant data sets and check for CDISC compliance., Atorus Research (atorus-research/xportr GitHub repository). Opened 12 Nov 2026.

sdtm.oak

pharmaverse · Publisher-published · open to run here

EDC-agnostic and data-standard-agnostic R package for building CDISC SDTM datasets, with reusable mapping algorithms for modular programming. The repository description says it transforms raw clinical data in ODM format to SDTM; the README says a code-generation feature from a standard SDTM specification is planned.

Apache-2.0 per the repository; the README installs it from CRAN. Not installed or run here.

Source: GitHub - pharmaverse/sdtm.oak: An EDC and Data Standard agnostic SDTM data transformation engine that automates the transformation of raw clinical data in ODM format to SDTM based on standard mapping , pharmaverse (pharmaverse/sdtm.oak GitHub repository). Opened 12 Nov 2026.

pharmaverse examples

pharmaverse · Publisher-published · open to run here

Book of end-to-end examples that chain pharmaverse packages for common clinical reporting analyses such as ADaM and tables, listings and graphs, using consistent test data from pharmaverseraw, pharmaversesdtm and pharmaverseadam.

Apache-2.0 per the repository. The rtables reporting-tables package is on CRAN as 0.6.17 under Apache License 2.0. Not installed or run here.

Source: GitHub - pharmaverse/examples: End to end examples of pharmaverse packages for common safety clinical reporting analyses, pharmaverse (pharmaverse/examples GitHub repository). Opened 12 Nov 2026. Also opened: CRAN page for rtables (reporting tables).

R submission Pilot 1

R Consortium · Publisher-published · open to run here

Tests whether an R-based submission package can meet the needs and expectations of FDA reviewers, including code review and reproducibility of analyses. The README states that all submission materials and communications are public and that this is an FDA-industry collaboration through the R Consortium, and lists the initial submission (2021-11-22) and an updated submission (2022-02-11) with FDA statistical reviews.

GPL-3.0 per the repository; organised as an R package (the README names R 4.1.3 on Ubuntu 20.04 as the tested environment). Not installed or run here.

Source: GitHub - RConsortium/submissions-pilot1: development repo for pilot1 submission to FDA, R Consortium (RConsortium/submissions-pilot1 GitHub repository). Opened 12 Nov 2026. Also opened: R Submissions Working Group: lists Pilots 1 to 3 as completed and Pilot 4 (container component) as under development.

R submission Pilot 2 (Shiny)

R Consortium · Publisher-published · open to run here

Tests whether a Shiny application written in R can be bundled into a submission package and transferred to FDA reviewers. The application uses the data and analyses from Pilot 1; a deployed copy is also available through shinyapps.io.

GPL-3.0 per the repository; the intent is execution in a reviewer's local R environment. Not installed or run here.

Source: GitHub - RConsortium/submissions-pilot2: development repo for pilot2 submission to FDA, R Consortium (RConsortium/submissions-pilot2 GitHub repository). Opened 12 Nov 2026.

R submission Pilot 3 (ADaM)

R Consortium · Publisher-published · open to run here

Delivers a publicly accessible R-based submission through the eCTD portal and extends Pilot 1 by using R to generate the ADaM datasets. The project website walks through background, deliverables sent to FDA (cover letter, TLFs, datasets, ADRG), conference proceedings and regulatory feedback.

GPL-3.0 per the repository. Not installed or run here.

Source: GitHub - RConsortium/submissions-pilot3-adam: Development repo for pilot3 submission to FDA - ADaM, R Consortium (RConsortium/submissions-pilot3-adam GitHub repository). Opened 12 Nov 2026.

R submission Pilot 4 (containers, WebAssembly)

R Consortium · Publisher-published · documented, not executed here

Builds on Pilot 2 to explore bundling the Shiny application with its execution dependencies using containers and WebAssembly; this repository covers the container version.

No licence shown on the repository page and listed as under development by the working group, so documented, not executed here.

Source: GitHub - RConsortium/submissions-pilot4-container, R Consortium (RConsortium/submissions-pilot4-container GitHub repository). Opened 12 Nov 2026.

SDTM/ADaM pilot project data

CDISC · Publisher-published · documented, not executed here

CDISC repository of clinical test data from the SDTM/ADaM pilot project, published for informational purposes under a disclaimer and terms of use.

Data under CDISC terms of use rather than an open-source licence (the terms forbid, among other things, distributing the data for a fee or without attribution to CDISC), so documented, not executed here. Read the terms in the README before any lab uses the files.

Source: GitHub - cdisc-org/sdtm-adam-pilot-project, CDISC (cdisc-org/sdtm-adam-pilot-project GitHub repository). Opened 12 Nov 2026.

phuse-scripts

PHUSE · Publisher-published · open to run here

Repository of the PHUSE CS Standard Analyses Working Group for delivering standard industry analyses and displays built on CDISC standards for analysis data.

MIT per the repository. Not installed or run here.

Source: GitHub - phuse-org/phuse-scripts: Delivery standard industry analyses, built upon CDISC standards for analysis data, PHUSE (phuse-org/phuse-scripts GitHub repository). Opened 12 Nov 2026.
