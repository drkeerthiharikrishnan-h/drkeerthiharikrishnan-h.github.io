Platform reference · Databricks

Databricks

Databricks is a lakehouse platform: data sits in open-format tables on cloud storage, governed by one catalog and queried with SQL, notebooks and dashboards. This page lists the parts a biopharma data team meets first (Delta Lake storage, Unity Catalog, the medallion pattern, Databricks SQL, dashboards) and the public health and life-science accelerators Databricks and open-source projects publish on GitHub: OMOP, FHIR, adverse drug events, genomics with Glow and data sharing.

Each entry is written from the page named as its source, opened on the date shown. A vendor's statement about its own product is tagged vendor-published; open-source projects, standards bodies and public agencies are tagged publisher-published. Nothing proprietary was run: an entry that is not executable here says "documented, not executed here".

Delta Lake on Databricks

Databricks · Vendor-published · documented, not executed here

The storage layer under tables in a Databricks lakehouse. It adds a file-based transaction log to Parquet data files, which gives ACID transactions and metadata handling at scale, and lets one copy of data serve batch and streaming work. On Databricks every table is a Delta Lake table unless stated otherwise. The page calls Delta Lake open source software and says Databricks first developed the protocol.

Managed cloud service that needs an account with the vendor; documented, not executed here. The open-source Delta Lake format can be used outside Databricks; that was not tried here.

Life-science example: Databricks solution accelerator whose notebooks ingest synthetic records into a Delta bronze layer and define OMOP 5.3.1 tables for Delta.

Source: What is Delta Lake in Databricks?, Databricks documentation. Opened 12 Nov 2026.

Unity Catalog

Databricks · Vendor-published · documented, not executed here

The governance layer for data and AI assets built into Databricks. When enabled it applies access control when a table is queried or a model is called, tracks lineage and logs activity for audit. Governed assets sit in a three-level namespace (catalog.schema.object). The page says it is enabled automatically for workspaces created after 8 November 2023.

Managed cloud service that needs an account with the vendor; documented, not executed here. The open-source Unity Catalog server has a local quickstart on its repository page; it was not run here.

Source: What is Unity Catalog?, Databricks documentation. Opened 12 Nov 2026. Also opened: Open-source Unity Catalog repository: Apache 2.0 licence, described as a sandbox project with the LF AI and Data Foundation.

Medallion lakehouse architecture

Databricks · Vendor-published · documented, not executed here

A data design pattern that moves data through layers of rising quality, named bronze (raw), silver (validated) and gold (enriched), also called a multi-hop architecture. Databricks recommends it; the page says following it is a recommended best practice but not a requirement. It is a pattern, not a product.

A design pattern described for Databricks; documented, not executed here. The same layering can be built with open-source tools, which was not tried here.

Life-science example: The OMOP accelerator lands synthetic CSV records in a Delta bronze layer before building OMOP tables.

Source: What is the medallion lakehouse architecture?, Databricks documentation. Opened 12 Nov 2026.

Databricks SQL

Databricks · Vendor-published · documented, not executed here

A cloud data warehouse built on the lakehouse that runs on the data lake directly, without moving the data. The page says it supports ANSI SQL with Delta Lake extensions and runs on SQL warehouses, reachable from a SQL editor, notebooks, scheduled jobs, dashboards, alerts and a REST API.

Managed cloud service that needs an account with the vendor; documented, not executed here.

Source: Data warehousing on Databricks, Databricks documentation. Opened 12 Nov 2026. Also opened: PyPI record of the Databricks SQL Connector for Python (version 4.9.0, Apache-2.0, Python >=3.10,<4.0 on the day opened).

AI/BI dashboards

Databricks · Vendor-published · documented, not executed here

Dashboards for building visualisations from tables, views or custom queries inside Databricks, with AI-assisted authoring, filters and calculated fields. The page says a published dashboard can be shared with anyone registered to the Databricks account, even without access to the workspace.

Managed cloud service that needs an account with the vendor; documented, not executed here.

Source: Dashboards, Databricks documentation. Opened 12 Nov 2026.

Sample datasets

Databricks · Vendor-published · documented, not executed here

Sample data that Databricks and third parties make available inside a workspace. The samples catalog in Unity Catalog lists schemas such as nyctaxi (New York City taxi trips), tpcds_sf1 and tpch (benchmark data) and wanderbricks (a simulated travel booking platform). None of the schemas listed on the page is a life-science dataset.

Managed cloud service that needs an account with the vendor; documented, not executed here. The datasets are reached from inside a workspace.

Source: Sample datasets, Databricks documentation. Opened 12 Nov 2026.

Solution accelerator: OMOP common data model on the lakehouse

Databricks · Vendor-published · documented, not executed here

Notebooks that build an OMOP 5.3.1 common data model for observational research on the Databricks lakehouse. They ingest synthetic Synthea records in CSV form into a Delta bronze layer, define the OMOP tables and vocabulary tables, run an example ETL from Synthea into OMOP and build an example patient cohort.

The notebooks target a Databricks workspace; documented, not executed here.

Source: databricks-industry-solutions/omop-cdm, GitHub repository databricks-industry-solutions/omop-cdm. Opened 12 Nov 2026.

Glow

Project Glow · Publisher-published · open to run here

An open-source toolkit for genomic data at biobank scale on Apache Spark. It loads VCF, BGEN and Plink files into distributed DataFrames, offers quality control and data manipulation functions, variant normalisation and liftOver, and genome-wide association studies, with queries in Spark SQL from Python, SQL, R, Java or Scala.

Open source (Apache-2.0 per the repository page); the page describes building it with sbt, Java 8 and a conda environment. Nothing was installed or run: documented, not executed here.

Life-science example: Databricks solution accelerator notebook for genome-wide association studies that builds on Glow.

Source: projectglow/glow, GitHub repository projectglow/glow. Opened 12 Nov 2026.

Solution accelerator: adverse drug events from conversational text

Databricks · Vendor-published · documented, not executed here

Notebooks for post-market drug safety monitoring that use existing Spark NLP models to process conversational text, extract adverse drug event and drug mentions, store the results in the lakehouse and analyse them. The page names Databricks and John Snow Labs as authors.

The notebooks target a Databricks workspace; documented, not executed here.

Source: databricks-industry-solutions/adverse-drug-events, GitHub repository databricks-industry-solutions/adverse-drug-events. Opened 12 Nov 2026.

dbignite

Databricks · Vendor-published · documented, not executed here

A library for analytics on FHIR bundles: it reads a bundle, extracts the resources and flattens them into tables. The README covers FHIR R4 and R5 schemas, SQL on FHIR, reading non-compliant FHIR data, writing FHIR data and an OMOP common data model section. It installs from the GitHub repository with pip.

A Spark library whose detailed demo is run inside Databricks; documented, not executed here.

Source: databricks-industry-solutions/dbignite, GitHub repository databricks-industry-solutions/dbignite. Opened 12 Nov 2026.

Delta Sharing

Delta Lake project · Publisher-published · documented, not executed here

An open REST protocol for exchanging large datasets between organisations whatever computing platform each uses; it shares access to part of a cloud dataset held on storage such as S3, ADLS or GCS. The repository holds the protocol specification, a Python connector that reads shared tables as pandas or Spark DataFrames, an Apache Spark connector and a reference server.

Apache License 2.0. The Python connector installs with pip, but reading data needs a share published by a provider; documented, not executed here.

Life-science example: Databricks accelerator that reads pre-processed social determinants of health tables made available by Rearc over Delta Sharing and relates them to county COVID-19 vaccination rates.

Source: delta-io/delta-sharing, GitHub repository delta-io/delta-sharing. Opened 12 Nov 2026.
