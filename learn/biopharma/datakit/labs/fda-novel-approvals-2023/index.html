1. The question

How many novel drugs did the FDA's drug centre (CDER) approve in calendar year 2023, and can that count be rebuilt from the agency's own application records in Drugs@FDA?

Regulatory intelligence teams count approvals all the time, for competitor tracking, forecasting and benchmarking. The agency publishes a curated list, and it also publishes the raw application records. Rebuilding the list from the records shows which fields carry the meaning of "novel", and where they do not.

From: Section FDA Novel Drug Therapy Approvals for 2023: the sentence giving the count, and the numbered list below it[1]

2. Where this data lives in a company

Systems of record
Regulatory information management
Owner
Regulatory affairs, or a regulatory intelligence group, reads public approval records like these alongside the company's own submissions.
Standards
None named by a source

Drugs@FDA is the agency's public record of approved applications (NDA, ANDA and many CDER biologics as BLA), each with its submissions, their type, status, date and review class. openFDA serves the same data as JSON with a bulk download. The FDA defines its novel list as CDER's new molecular entities and new therapeutic biological products by calendar year.[2][3][4]

6. What goes wrong in practice

  • A filter on applications is not a filter on submissions. A filter written on whole applications ("has an original submission" and "has an approval dated 2023") lets in old applications that only had a supplement approved in 2023. The notebook counts both ways to show the size of the gap. Filter single submissions. Seen in this lab's data; the notebook shows it.
  • Novel is a curated list, not a field. The agency defines its list as CDER's new molecular entities and new therapeutic biological products. For an NDA the review class Type 1 carries most of that meaning. For a BLA no documented field separates a new biologic from a biosimilar, so a rule on the records alone can count more than the list. [2][3]
  • The rule finds every listed drug and twelve more. On the run of 11 Nov 2026 (zip last_updated 2026-11-11) the rule counted 67 against the 55 printed. The run of 14 Nov 2026 (zip last_updated 2026-11-13) gave the same count. All 55 listed drugs were found (38 NDAs and 17 BLAs). The 12 extra were all BLAs whose class code is not Type 1 (Type 2, 3 or 5, or UNKNOWN); several carry brand names that match or extend biologics already on the market (Eylea HD and Eylea, Entyvio, Cosentyx). The records do not say which of them are biosimilars. The lab does not reproduce the published count, and the difference sits entirely in the BLA part of the rule. Seen in this lab's data; the notebook shows it.
  • The size of the application-level error. On the same run the whole-application filter returned 864 NDAs and 169 BLAs; the single-submission filter returned 107 NDAs and 29 BLAs. The run of 14 Nov 2026 (zip last_updated 2026-11-13) gave the same counts. Seen in this lab's data; the notebook shows it.
  • The record and the list can both change. The bulk file is re-exported often and the list page has its own update date. Note the file's last_updated date and the page date with every count. [1]

7. The same job on each platform

  • Open source executed here The lab's notebook reads the openFDA Drugs@FDA bulk JSON file, tabulates it with pandas, keeps the original 2023 approvals (NDAs with review class Type 1 and every original BLA), compares the count with the 55 novel drugs FDA lists for 2023, and matches the result drug by drug against FDA's list. This site's check runs it in a fresh Python process.[6]
  • Open source documented, not executed herepublisher-published DuckDB is a SQL database that runs inside the calling program and reads JSON files from disk. A learner could unzip the Drugs@FDA bulk file and select the original 2023 approvals with SQL, then compare the count with the notebook's. Not done here.[7]
  • AWS documented, not executed herevendor-published Amazon Athena is an interactive query service that runs standard SQL directly on data in Amazon S3. A learner with an account could put the unzipped Drugs@FDA file in a bucket and count the original 2023 approvals with a query. Not done here.[8]
  • Google Cloud documented, not executed herevendor-published BigQuery is a managed, serverless data platform for managing and analysing data with SQL and Python. A learner with a Google Cloud project could load the Drugs@FDA records into a table and count the 2023 novel approvals with SQL. Not done here.[9]
