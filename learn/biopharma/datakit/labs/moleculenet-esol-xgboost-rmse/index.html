Reproducing a benchmark's published model score for aqueous solubility (MoleculeNet ESOL)

This lab reproduces a benchmark's published model score; it is not a measurement and not a new model. Train a gradient-boosted tree model (XGBoost) on ECFP4 fingerprints of the 1,128 compounds in the MoleculeNet ESOL solubility set and compare its test RMSE with the 0.99 log units that the MoleculeNet paper prints in its Table 3.

Reproduced here: 2 of 2 published values match (checked 14 Nov 2026).

1. The question

How close does a gradient-boosted tree model (XGBoost) on ECFP4 molecular fingerprints get to the test error that the MoleculeNet benchmark paper prints for aqueous solubility (the ESOL set, random split)?

A benchmark score is only useful if someone else can get it again from the same data. Rebuilding it shows what a published model score depends on (the featurisation, the split, the seeds, the hyperparameters, the number of test compounds) and how far apart two honest runs can be. It is the check a computational chemist makes before trusting a leaderboard number.

From: Table 3, row ESOL, metric RMSE, column Best performances - conventional methods (XGBoost: 0.99); Table 1, row ESOL (1128 compounds, random split, RMSE)[1]

6. What goes wrong in practice

  • A benchmark score is an average over splits. The paper reports the mean of three runs with different random seeds and does not print the seeds. With about 113 compounds in each test subset, one split can give a different RMSE from the next. Compare averages, and report how many runs and which seeds you used. [1]
  • The paper tuned its hyperparameters; this lab does not. The paper ran a brief Gaussian-process hyperparameter search on the validation subset for each dataset and model. The paper points to its supplement for details; the supplement was not opened for this lab. This lab uses the preset values DeepChem 1.3.0 ships for XGBoost regression, the search's starting point. A gap between the two scores may come from this. [1][3]
  • Know which file you have. delaney-processed.csv is a processed file published by DeepChem for the MoleculeNet ESOL benchmark. Its relation to the supplement of Delaney's 2004 paper is not shown here. Name the file and its publisher when you quote a score. [1][4]
  • ECFP4 means radius 2. The paper says it uses ECFP4 fingerprints from RDKit. In DeepChem 1.3.0 that is a Morgan fingerprint of radius 2 folded to 1,024 bits, with bond types and without chirality. A radius of 4, or 2,048 bits (the CircularFingerprint default size), is a different featurisation. [1][5][6]
  • Old code, new libraries. The 1.3.0 code passes seed to XGBRegressor, gives early_stopping_rounds to fit and reads best_ntree_limit. The xgboost release this lab runs on names these random_state, a constructor argument and best_iteration (plus one); these newer names are as seen in the notebook, not in the DeepChem files. Settings the 2017 code left to library defaults, such as the tree method, may now default differently. Pin versions, and write down every setting a library default decides. [7][8]
  • The scale of y matters to some settings. DeepChem 1.3.0 normalises the measured values over the whole file before splitting. The RMSE is computed after the values are put back, but max_delta_step and reg_lambda act on the normalised scale, so the same settings on raw values give a different model. [4][3]

7. The same job on each platform

  • Open source executed here The lab's notebook reads the ESOL file with pandas, builds ECFP4 fingerprints with RDKit and makes random 80/10/10 splits with numpy, as DeepChem 1.3.0 did, and uses scikit-learn for the grid search. It fits an XGBoost regressor set up as DeepChem 1.3.0 did, over three runs, and compares the test RMSE with the 0.99 printed in the MoleculeNet paper. This site's check runs it in a fresh Python process.[9][10][11][12][13]
  • Google Cloud documented, not executed herevendor-published Cloud Storage stores unstructured data as objects in buckets that belong to a project. The page lists storing datasets for analytics and machine learning among its uses. For this lab a learner would keep the ESOL file and the split assignments in a bucket, so that each training run reads the same inputs. Not done here.[14]
  • Visualisation tools documented, not executed herevendor-published Streamlit is an open-source framework for data apps and dashboards, written in Python. For this lab a learner would build an app that shows measured against predicted solubility for the test compounds and the RMSE of each run beside the value in the paper. Not done here.[15]
