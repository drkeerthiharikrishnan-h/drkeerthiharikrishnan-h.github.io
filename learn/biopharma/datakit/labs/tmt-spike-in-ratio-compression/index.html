Designed against measured ratios in a TMT spike-in experiment

1. The question

Do the four spiked proteins show their designed abundance ratios across the six TMT reporter channels, and how much are the measured ratios compressed towards 1?

Isobaric labels such as TMT let one mass spectrometry run compare several samples, and they are used to measure how a treatment changes protein levels. A spike-in experiment with known ratios shows how close the measured ratios come to the truth, and in which direction they err.

From: PRIDE Archive API record PXD000001, field projectDescription (Expected reporter ion ratios for the Erwinia background and the enolase, BSA, phosphorylase B and cytochrome C spikes)[1]

6. What goes wrong in practice

  • A design is not a measurement. The record gives the ratios the experiment was designed to have. It gives no measured values and no pipetting error. Comparing measured ratios with a design tests the whole chain, from sample preparation to the mass spectrometer. [1]
  • Channel order is implied, not stated. The record lists six numbers per protein without naming the channels. The mzTab metadata maps its six abundance columns to TMT reagents 126 to 131. Reading the design in the same order is an inference; check it by eye against the data. [1]
  • Pick the reference channel per protein. Each protein's design has a channel at 1, but not the same channel (129 for enolase, 130 for phosphorylase B, 126 for the others). Dividing by that channel makes the expected ratio equal to the printed number. [1]
  • An old file layout. This mzTab predates the 1.0 format. Its metadata keys carry a prefix and its abundance columns are called peptide_abundance_sub[1] to [6]. Read it as plain tab-separated text, by line prefix. Seen in this lab's data; the notebook shows it.
  • The large ratios come out smaller than designed, and the lab says so. Run on 12 Nov 2026, the background, phosphorylase B and cytochrome C ratios fall within 0.5 of the design, but every enolase and BSA ratio designed at 2.5 or more comes out smaller. Enolase, designed at 10 in channels 126 and 131, measures about 4.5 and 4.1; BSA, designed at 10 in channel 129, measures about 6.7. All move in the designed direction. This site's check records the lab as not reproduced. So the large ratios come out smaller than the spike-in design implies. Several causes are possible; none is established here, and the lab does not correct for it. Seen in this lab's data; the notebook shows it.

7. The same job on each platform

  • Open source executed here The lab's notebook downloads the PRIDE mzTab file, splits its lines by prefix, reads the peptide table with pandas, divides each spike's peptides by its reference channel, takes medians with pandas, and compares the six channel ratios with the designed ones; numpy supplies log2 for the compression display. This site's check runs it in a fresh Python process.[3][4]
  • AWS documented, not executed herevendor-published Amazon S3 is an object storage service that stores and protects data for uses the page lists, including data lakes, archive and big data analytics. A learner could keep the mzTab file in a bucket as the notebook's input. Not done here.[5]
  • Microsoft documented, not executed herevendor-published Azure Data Lake Storage is a set of capabilities for big data analytics built on Azure Blob Storage, which the page calls the foundation for enterprise data lakes on Azure. A learner could keep the mzTab file there as the notebook's input. Not done here.[6]
  • Open source documented, not executed herepublisher-published DuckDB is an analytical SQL database that runs inside the calling program, with no separate server, and reads CSV, Parquet, JSON and Excel files. After the notebook's line-prefix step, a learner could save the peptide table as CSV and compute per-protein channel medians in SQL. Not run here.[7]
