Survey-weighted obesity prevalence from NHANES

Compute the share of US adults with obesity and severe obesity in August 2021 to August 2023 from the NHANES public-use files, with survey weights, design-based standard errors and age adjustment, and check every number against the agency's data brief.

1. The question

What share of US adults age 20 and older had obesity (BMI 30 or more) and severe obesity (BMI 40 or more) in August 2021 to August 2023, overall, by sex and by age group?

A survey sample is not a simple random sample. Each person stands for a different number of people, and people are sampled in clusters. A prevalence estimate needs the weights, and its standard error needs the design. The agency publishes both, so every step can be checked.

From: Page 7, data table for Figure 1; page 8, data table for Figure 3[1]

2. Where this data lives in a company

Systems of record
Warehouse or lakehouse
Owner
The National Center for Health Statistics (CDC) collects and publishes NHANES. A company that uses it holds a downloaded copy; it does not own the data.
Standards
None named by a source

NHANES files are SAS transport files, one per survey component. This lab joins DEMO_L and BMX_L on the respondent sequence number SEQN; the join is the lab's own step. Each file has its own codebook page. Weights and design variables sit in the demographics file. None of the standards in this kit's registry applies.[2][3]

Not sourced yet: That an epidemiology or real-world-evidence team keeps national survey files such as NHANES in its analytics warehouse, next to licensed claims and records data, has no opened source yet. The system listed is the closest id in the kit's registry; the kit has no id for public survey data.

6. What goes wrong in practice

  • The exam weight, not the interview weight. BMI is measured at the mobile examination centre, so the estimate uses WTMEC2YR. The interview weight WTINT2YR belongs to questions asked in the interview (at home or by telephone). People who were interviewed but not examined have an exam weight of 0. [2][1]
  • Pregnancy has three codes. RIDEXPRG is 1 for pregnant, 2 for not pregnant and 3 when it could not be determined. It exists only for women 20 to 44. The brief excludes pregnant women, and the codebook defines code 1 as pregnant. In this lab's notebook the brief's sample sizes are reproduced only when code 3 is kept, so drop code 1 only. [2][1]
  • Crude and age-adjusted are different numbers. The brief prints a crude percent for every row and an age-adjusted percent for adults 20 and older. For men the crude obesity percent is 39.2 and the adjusted one 39.3. Name which one you report. [1]
  • The standard population is fixed. Age adjustment uses the Census 2000 population and three age groups (20-39, 40-59, 60 and older). Another standard or other age groups give another number, and it cannot be compared with the brief. [1][5]
  • Keep the whole design when you estimate a subgroup. A subgroup (a subpopulation or domain) needs the whole design for its standard error. The NHANES variance estimation tutorial says to read the entire file of examined people with an exam weight into the software, with an indicator for the subgroup. Subsetting the file to the subgroup first treats the subgroup sample size as fixed and underestimates the variance. The notebook's domain flag is that indicator. [6]
  • A new cycle, a new design. The August 2021-August 2023 cycle uses an updated sample design, with strata 173 to 187 and two PSUs each, and it dropped oversampling by race, Hispanic origin and income. Code written for earlier cycles, with their weight names and pooled weights, does not carry over unchanged. [2][1]
  • A zero weight is not read as zero. The codebook gives WTMEC2YR the value 0 for people who were interviewed but not examined. pandas reads those values as 5.397605e-79, so a test for == 0 finds none of them. Select people by examination status (RIDSTATR), not by testing the weight. Seen in this lab's data; the notebook shows it.

7. The same job on each platform

  • Open source executed here The lab's notebook reads the DEMO_L and BMX_L transport files with pandas, joins them on SEQN, computes weighted, age-adjusted prevalence and design-based standard errors with numpy, and checks each value against the NCHS data brief. This site's check runs it in a fresh Python process.[7][8]
  • Databricks documented, not executed herevendor-published Delta Lake is the storage layer under tables in a Databricks lakehouse; it adds a transaction log to Parquet data files. A learner with an account could store the joined DEMO_L and BMX_L records as one Delta table for the analysis. Not done here.[9]
  • Snowflake documented, not executed herevendor-published Snowpark libraries for Java, Python and Scala query and process data inside Snowflake without moving it to the machine where the code runs. A learner with an account could load the joined files into a table and compute the weighted prevalence there with the Python library. Not done here.[10]
  • Microsoft documented, not executed herevendor-published Power BI connects to data, visualises it and shares it, with Power BI Desktop for building reports and the Power BI service for viewing and sharing them. A learner could build a report of obesity and severe obesity prevalence by sex and age group. Not done here.[11]
