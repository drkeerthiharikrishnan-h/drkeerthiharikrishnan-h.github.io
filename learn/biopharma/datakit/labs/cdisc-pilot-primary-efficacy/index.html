1. The question

In study CDISCPILOT01, does the change in ADAS-Cog (11) from baseline to Week 24, in the efficacy population with LOCF for missing Week 24 values, show a dose response across placebo, low-dose and high-dose xanomeline?

ADAS-Cog (11) at Week 24 is one of the study's two primary efficacy endpoints. Rebuilding its table shows every step from a collected score to a reported p-value.

From: Synopsis (PDF pages 3 to 6) and Table 14-3.01 (PDF page 468)[1]

2. Where this data lives in a company

Systems of record
Electronic data capture, Warehouse or lakehouse
Owner
Trial statistician. ICH E9 Statistical Principles for Clinical Trials (1998) gives this role, in collaboration with other clinical trial professionals, the task of making sure statistical principles are applied appropriately in trials that support drug development.
Standards
CDASH, SDTM, ADaM, Define-XML

Collection forms that follow CDASH can be loaded into an EDC system, and CDASH fields trace into SDTM. SDTM holds the tabulation data; CDISC names warehousing as one of its uses. ADaM holds the analysis datasets and traces back to SDTM. The report table is computed from ADaM.[2][3][4][5]

Not sourced yet: Which team builds the SDTM and ADaM datasets day to day, and which system stores them, has no opened source yet.

6. What goes wrong in practice

  • Zero does not read back as zero. Read with pandas, the placebo dose (0) and every zero change from baseline come back as about 5.4e-79. A filter such as TRTPN == 0 then finds nothing. The notebook sets these values to 0 right after reading. Seen in this lab's data; the notebook shows it.
  • A variable label in the file is wrong. In the ADQSADAS file header, CHG carries the label "Baseline Value", the same label as BASE. Check a variable against the define file and the values, not only its label. Seen in this lab's data; the notebook shows it.
  • Carried-forward values look like observed values. The primary analysis fills a missing Week 24 score with the last earlier score (LOCF). In the Week 24 analysis set, the notebook counts 79 of the 234 values as carried forward; this count is observed in the notebook and is not printed in either source. Only the DTYPE column tells them apart, so count them before you read the result. [7][1]
  • DM holds more people than the analysis. SDTM DM has 306 rows because it includes 52 screen failures. ADSL has 254 subjects, and the efficacy population is 234. The N in the table header is the efficacy population, not everyone in a treatment arm. Seen in this lab's data; the notebook shows it.
  • The dates are not the real dates. The report says dates were changed and moved into the future when the data were de-identified, with the order of events kept for each subject. Use intervals between dates, never calendar dates. [1]

7. The same job on each platform

  • Open source executed here The lab's notebook reads the pilot SDTM and ADaM transport files with pandas, fits the linear models for the ADAS-Cog (11) table with statsmodels, and checks each number against the study report. This site's check runs it in a fresh Python process.[8][9]
  • Submission tooling documented, not executed herepublisher-published The pharmaverse examples book chains pharmaverse R packages for common clinical reporting analyses, such as ADaM and tables, listings and graphs, on pharmaverse test data. A learner would follow its table examples in R to build a summary table from ADaM data and compare its layout with this lab's table. Not done here.[10]
  • Visualisation tools documented, not executed herepublisher-published teal is a Shiny-based framework of exploratory web apps for analysing clinical trial data. App developers specify the data, which can be CDISC data, and the analysis modules. A learner could load the pilot ADaM datasets into a teal app to explore ADAS-Cog (11) scores by treatment arm. Not done here.[11]
  • Submission tooling documented, not executed herepublisher-published CDISC's repository provides clinical test data from the SDTM/ADaM pilot project for informational purposes, under a disclaimer and terms of use. It holds this lab's input datasets. A learner could read the terms on the repository page before downloading the SDTM and ADaM files. Not done here.[12]
