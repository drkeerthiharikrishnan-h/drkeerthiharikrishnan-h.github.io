1. The question

How often are TP53 and PIK3CA (and the other genes named in the same table row) mutated in each PAM50 subtype of breast cancer? Computed from the cBioPortal study brca_tcga_pub for the tumours that have mutation, copy-number and expression data, compared with the "DNA Mutations" row of Table 1 of the TCGA Nature 2012 paper.

The published percentage depends on which set of tumours is the denominator and on whether a silent change counts as a mutation. Rebuilding the table from the portal's API shows both choices, and how a population choice alone can move a result far more than a gene's biology does.

From: Table 1 ("Summary of disease subtypes findings…"), row "DNA Mutations", columns Luminal A, Luminal B, Basal-like, HER2E[1]

6. What goes wrong in practice

  • The paper prints two different sets of percentages. The Results text and Figure 1 give mutation frequencies on the sequenced tumours, 510 tumours from 507 patients (the portal's 507-sample list); Table 1 gives them on the 466-tumour "overlap list", the 466 tumours from 463 patients with data on five platforms. This lab reproduces Table 1 only, using the portal's "Complete samples" list (463), never the 507-sample sequenced list and never all 825 samples in the study. [1]
  • The denominator is every sample of the subtype, mutated or not. A sample with no row in a gene's mutation file is still in the denominator. Counting only samples that happen to appear in a gene file as the denominator would inflate every percentage. Seen in this lab's data; the notebook shows it.
  • Count samples, not mutation rows. PIK3CA has 195 rows in 179 samples; MAP3K1 has 66 rows in 39 samples. A sample with two mutations in the same gene must only be counted once. Seen in this lab's data; the notebook shows it.
  • A synonymous change is still a row in the file, but not a mutation here. The portal re-annotates mutation calls (cBioPortal FAQ). In these files, five rows across the genes carry a protein change ending "=" (a change that does not alter the protein) and the portal classes them Splice_Region (counted in the notebook). The paper's Figure 1 legend describes non-silent mutations for the sequenced tumours; Table 1's "DNA Mutations" row itself carries no qualifier. This lab drops the five rows, which changes two of the published cells by one sample (Basal-like TP53 and HER2E PIK3CA). [1][2] Seen in this lab's data; the notebook shows it.
  • Table 1's "HER2E" is the portal's "HER2-enriched". The column header in the paper and the PAM50 value returned by the API use different spellings of the same subtype. The pam50 file also has only 522 entries for 825 samples; a sample with no entry has no PAM50 value and is not in any of the four table columns. Seen in this lab's data; the notebook shows it.
  • Two Luminal cells differ under the default tolerance. The lab uses the default rule (half a unit of the last printed digit) for every cell. Run on 14 Nov 2026, two cells differ, so this site's check records the lab as not reproduced (12 of 14 checks). Luminal A TP53 comes out 11.48 against a printed 12, and Luminal B PIK3CA 31.25 against 32. A population difference is a possible reason, not an established one. The portal's "Complete samples" list holds one tumour per patient (463); the paper's Table 1 footnote is based on 466 tumours from 463 patients. Comparing Figure 1's subtype sizes with the portal's 507-sample list (sizes counted in the notebook) suggests one of the three extra tumours is Luminal A and two are Luminal B. But the Figure 1 legend groups 501 tumours while 510 were sequenced, and the portal's PAM50 labels may not equal the paper's. This cannot be checked from open files. An earlier version of this lab widened the two Luminal tolerances after these two cells had been seen; that was reverted on 14 Nov 2026. [1] Seen in this lab's data; the notebook shows it.

7. The same job on each platform

  • Open source executed here The lab's notebook calls the cBioPortal web API with the Python standard library, reads the JSON answers (sample lists, PAM50 calls and gene mutation rows) with the standard library, drops synonymous changes, computes the share of mutated samples per subtype on the complete-samples list, compares it with Table 1, and shows the table with pandas. This site's check runs it in a fresh Python process.[4]
  • Visualisation tools documented, not executed herepublisher-published The cBioPortal repository describes a portal, licensed under the Apache License 2.0, for visualisation, analysis and download of large-scale cancer genomics data sets. A learner would open study brca_tcga_pub on the public portal and look at the genes of Table 1 there. Not done here.[5]
  • AWS documented, not executed herevendor-published The registry page lists an open S3 bucket, readable with no AWS account, holding TCGA masked somatic mutation data from the Genomic Data Commons, and a controlled bucket for raw and annotated calls. A learner could look there for the breast cancer project's mutation files. Their presence, and any match with the file used here, is not checked.[6]
  • Open source documented, not executed herepublisher-published DuckDB is an analytical SQL database that runs inside the calling program, with no separate server, and reads CSV, Parquet, JSON and Excel files. A learner could save the API's JSON answers as files and join mutation rows to PAM50 calls per sample in SQL. Not run here.[7]
