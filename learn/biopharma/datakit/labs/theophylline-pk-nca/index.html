1. The question

For the 12 subjects given one oral dose of theophylline, what are the peak concentration (Cmax), the time of the peak (Tmax), the terminal half-life and the area under the concentration-time curve (AUC), computed by non-compartmental analysis? Do the values agree with the summary table of the PKNCA package's theophylline vignette?

Non-compartmental analysis (NCA) is the standard first computation on serum concentration data from a dosing study. The US FDA guidance on bioavailability studies submitted in NDAs or INDs (April 2022) uses Cmax and AUC to assess bioavailability.

From: Section 'Compute the parameters', the table printed after summary(results_obj_automatic) (HTML page, no page numbers)[1]

SDTM

The ICH guideline M10, Bioanalytical Method Validation and Study Sample Analysis (2022), says concentration measurements of drugs in biological matrices contribute to regulatory decisions on safety and efficacy. It lists a laboratory information management system (LIMS) among the documentation kept at the analytical site. The US FDA guidance Bioavailability Studies Submitted in NDAs or INDs - General Considerations (2022) recommends to sponsors of those studies that Cmax be taken directly from the concentration data without interpolation, that AUC0-t run to the last measurable concentration, and that AUC0-INF equal AUC0-t plus the last concentration over lambda-z. CDISC describes SDTM as "a standard for organizing and formatting data".[2][3][4]

6. What goes wrong in practice

  • Half-life is an arithmetic mean, not a geometric one. The vignette's half.life column is arithmetic mean [standard deviation], unlike cmax and the AUC columns which are geometric mean [geometric %CV]. Summarising half-life geometrically gives a different pair of numbers and does not match the published table. [6]
  • auclast appears twice, for 0-24 h and for 0 to the last sample. The vignette prints auclast twice: 74.6 [24.3] is the AUC from 0 to 24 hours (dropping any sample past 24.00 h), and 98.7 [22.5] is the AUC from 0 to the last sample (which differs per subject, up to about 24.65 h). Confusing the two intervals is an easy mistake. Seen in this lab's data; the notebook shows it.
  • The AUC rule is linear-up/log-down, not all-linear. Using a simple linear trapezoidal rule on the whole falling curve gives noticeably different auclast and aucinf.obs numbers from the published ones. The provenance block printed in the Multiple Dose Example section of the same vignette states its auc.method as 'lin up/log down': linear trapezoid while concentration is rising or flat, logarithmic trapezoid while it is falling to a positive value. [1]
  • Terminal-phase point selection is not simply 'the last three points'. PKNCA's automatic method tries the last 3, 4, 5 ... points after Tmax and keeps the one with the most points whose adjusted R-squared is within 0.0001 of the best adjusted R-squared seen. Taking a fixed last-three-points window gives different lambda.z and half-life values for several subjects. [6]
  • numpy and pandas disagree on the default standard deviation. numpy's std() defaults to a population standard deviation (ddof=0); pandas' .std() defaults to a sample standard deviation (ddof=1). The published half-life SD and the geometric %CV figures were computed with ddof=1 throughout. Seen in this lab's data; the notebook shows it.

7. The same job on each platform

  • Open source executed here The lab's notebook loads the 12-subject concentration CSV with pandas, computes Cmax, Tmax, AUC and the terminal half-life from a log-linear fit with numpy, and checks the summary against the PKNCA theophylline vignette. This site's check runs it in a fresh Python process.[7][8]
  • AWS documented, not executed herevendor-published Amazon S3 is object storage, with management features to organise data and configure access. A learner with an account could keep the concentration CSV and the computed parameter table as objects in a bucket, with the GPL notice kept beside any stored copy. Not done here.[9]
  • Snowflake documented, not executed herevendor-published Snowpark libraries for Java, Python and Scala query and process data inside Snowflake without moving it to the machine where the code runs. A learner with an account could load the concentrations into a table and compute Cmax and Tmax per subject with the Python library. Not done here.[10]
  • Visualisation tools documented, not executed herevendor-published Shiny builds interactive web apps from R code whose outputs update when user inputs change, with widgets such as plots, tables and sliders. A learner could build an app that plots one subject's concentration-time curve and shows that subject's NCA parameters. Not done here.[11]
