1. The question

Which genes mark each of the two CD68-positive macrophage populations, compared with all other liver cells?

Marker genes are how a single-cell study names its cell populations, and later studies reuse them to find the same cells in tissue or in disease. Checking a printed marker list against the deposited data shows what the list means (which comparison, which cells) and how stable gene names are.

From: Results, section Intrahepatic monocytes/macrophages, paragraph 1 (population 1, Cluster 4, Top DE genes) and paragraph 2 (population 2, Cluster 10, top DE genes)[1]

CELLxGENE Discover distributes each dataset as one AnnData (h5ad) file in a versioned schema, with cell metadata (obs), gene metadata (var) and the expression matrix. The curation API gives the dataset's cell count, schema version, file size and citation string.[2][3]

6. What goes wrong in practice

  • A marker list needs its comparison. The paper says its DE test was a likelihood-ratio test in Seurat but does not say against which cells each cluster was compared. The authors' code compares each cluster with all other cells and keeps genes that are higher. A gene on such a list can still be higher in another cell type, or in the other macrophage population. [1][4]
  • Gene names change between references. The paper used the Cell Ranger GRCh38 1.2.0 reference. A curated copy of the data may name genes differently (the pitfall "A name found in only one of two columns" shows this file's case). Clone-based names such as RP11-1143G9.4 may no longer exist, and the paper prints AIF1l in mixed case. Match names with care and report a name that is not found rather than dropping it. [1]
  • Two kinds of cell-type label. This file carries the authors' labels (CellType, BroadCellType) and a Cell Ontology label (cell_type). The authors' "Inflammatory Macs" and "Non-inflammatory Macs" are "M1 macrophage" and "macrophage" in the ontology column and both fall under "Kupffer" in the broad label. The file has no cluster number, so the match of these two labels to the paper's Cluster 4 and Cluster 10 is by name. Pick the population by the authors' label. Seen in this lab's data; the notebook shows it.
  • X is not always raw counts. In this file X holds normalised values and raw/X holds the counts, both 8,444 cells by 32,088 genes. Check that the values you normalise are whole numbers before you divide by library size. Seen in this lab's data; the notebook shows it.
  • One printed marker is not higher here. The paper's list for non-inflammatory macrophages prints AIF1l. Matched to AIF1L, it is not higher in that population than in all other cells in this file, so this check differs. The table of section 4 shows it detected in about 0.3 percent of the non-inflammatory macrophages. No opened source says which gene the paper means. The check stays as printed. Seen in this lab's data; the notebook shows it.
  • A name found in only one of two columns. The curated file has two gene name columns, the authors' gene_symbols and feature_name. RP11-1143G9.4 is found only in the authors' gene_symbols column; the found_in column of the table in section 4 shows this. A lookup that uses feature_name alone would report the gene as missing. Seen in this lab's data; the notebook shows it.
  • The lab's test is simpler than the paper's. The paper normalised with scran (pool-and-deconvolute size factors) and tested with a likelihood-ratio test in Seurat. This lab divides each cell's counts by its library size, multiplies by 10,000, takes log1p, and checks only the sign of the mean difference. That is a simpler stand-in, so a weak marker's direction could in principle differ from the paper's result. [1]

7. The same job on each platform

  • Open source executed here The lab's notebook downloads the CELLxGENE Discover h5ad file, opens it with h5py, reads the raw counts as a scipy sparse matrix, normalises and log-transforms them with numpy, and with pandas checks that each printed marker gene is higher in its population than in all other cells. This site's check runs it in a fresh Python process.[5][6][7][8]
  • Visualisation tools documented, not executed herepublisher-published The repository describes CZ CELLxGENE Annotate, an interactive explorer for single-cell data, installed with pip and launched on an AnnData (h5ad) file. A learner could launch it on this lab's h5ad file and explore the two macrophage populations and the printed marker genes. Not run here.[9]
  • Visualisation tools documented, not executed herepublisher-published The Census is a free-to-use service, API plus data, for querying the CZ CELLxGENE Discover single-cell corpus directly into Python or R. A learner could query this dataset's liver cells from the corpus instead of downloading the h5ad file. Whether the dataset is in the current Census release is not checked here.[10]
  • Google Cloud documented, not executed herevendor-published Cloud Storage stores unstructured data as objects in buckets that belong to a project; objects can be uploaded and downloaded. A learner could keep the h5ad file in a bucket and download it from there before running the notebook. Not done here.[11]
