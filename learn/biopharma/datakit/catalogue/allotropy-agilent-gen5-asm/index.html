Plate-reader export and its Allotrope Simple Model (ASM) conversion, a paired test fixture in the allotropy library

A Gen5 plate-reader text export and the ASM JSON that Benchling's open-source allotropy library (parser agilent_gen5) is expected to produce from it, kept as a paired test fixture.

Dataset card Discovery · Benchling, Inc. (Benchling-Open-Source/allotropy on GitHub)

allotropy is a Python library by Benchling for converting text or Excel instrument software output into JSON that conforms to the published Allotrope Simple Model (ASM) schema; its README says it does not convert proprietary binary formats, and the latest release on PyPI is 0.1.152 (Python 3.10 or higher). Under tests/parsers/agilent_gen5/testdata the repository keeps a pair of files for one 'Fibrillation data' run. The input is a tab-separated export from Gen5 software version 3.15.15 for a Synergy H1 reader, with procedure details (96-well plate, temperature setpoint, fluorescence endpoint reads with filter sets) followed by the readings. The expected output is an ASM plate-reader document under the manifest plate-reader/REC/2025/03, produced by converter allotropy_agilent_gen5 version 0.1.143, with 96 plate reader documents (6 measurement documents each, with sample, device control, temperature and fluorescence fields) and 2,592 calculated data documents. The input file embeds the original lab's file path and the reader's serial number; neither is repeated here.

MIT License (Copyright (c) 2023 Benchling, Inc.). The MIT licence is stated for the repository as a whole; no separate statement covers the test fixtures. The input file carries a lab file path and an instrument serial number, so link to the files and store no excerpt.
Data dictionary
allotropy README
Good for
  • Seeing what a vendor plate-reader export looks like next to the same data in a vendor-neutral schema, field by field.
  • Understanding why instrument data are converted to a common model before they reach a LIMS or data lake, and what metadata (software, reader model, plate layout) travels with them.

Why this is not a lab: No published result located. The expected JSON is a software test fixture: it fixes what the converter should output, not a scientific result. A notebook could run the converter and compare files, but that tests the library rather than an analysis, so the pair is catalogued for data-engineering practice.
