MIMIC-IV Clinical Database Demo on FHIR, version 2.1.0 (records of 100 patients as FHIR resources)

The 100-patient MIMIC-IV demo converted to HL7 FHIR resources, published openly on PhysioNet as newline-delimited JSON.

Dataset card Real-world · PhysioNet; authors Bennett, Ulrich, Wiedekopf, Szul, Grimes and Johnson, as given in the citation on the page of version 2.1.0

The project converts real, de-identified hospital records of 100 patients into FHIR R4 resources. The page of version 2.1.0 says the resources come from the MIMIC-IV Clinical Database Demo v2.2 and the MIMIC-IV-ED Demo v2.2. Its README says the files are gzipped NDJSON, one complete resource per line, and that resources point to each other by reference, for example an observation to its patient through subject.reference. The folder listing of version 2.1.0 shows 30 files, 7 of them for emergency-department data. Version 2.0, of June 7, 2022, is still on PhysioNet: its folder listing shows 22 uncompressed NDJSON files and none for the emergency department. The two version pages, the README, the licence text, the two folder listings and the paper were opened for this card; no data file was downloaded.

The licence asks for attribution and share-alike. This card links to the files at PhysioNet and stores no copy and no preview.

Standards
FHIR
Good for
  • Seeing how patients, encounters, observations and medication requests are written as linked FHIR resources.
  • Practising reading NDJSON and following subject and encounter references between resources.
  • Comparing the same kind of records in three forms: native tables (card mimic-iv-demo), the OMOP common data model (lab mimic-omop-demo-achilles-counts) and FHIR.

Why this is not a lab: No published result located. Counts for a demo are in print, but not for a release that can be named. Table 1 of the paper MIMIC-IV on FHIR (J Am Med Inform Assoc 2023) has a column of demo resource counts for 25 profiles, 915 281 in all, and the paper cites version 2.0 of this demo. Four of those rows have ED in the profile name, yet the folder listing of version 2.0 shows no file with ED in its name. Version 2.1.0 has such files, but it was published in 2025, after the paper, and its file names do not match the table: six profiles in its folder have no row in Table 1, and one row of Table 1 (MimicObservationVitalSigns) has no file of that name. So the release that the printed counts describe could not be named without guessing, and a lab would test version drift, not reproduction. Neither release was counted against the table. This candidate is a card, not a lab on version 2.0.
