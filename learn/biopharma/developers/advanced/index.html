    What you will be able to do

    • Specify a retrieval or prediction task by its label, unit of prediction, identifiers and split before choosing a model, and key features and knowledge-graph nodes on public identifiers stored with their release.
    • Build and test retrieval over regulated documents: chunks with locators, filters on controlled codes, BM25 and dense search fused by rank, reranking, and answers that cite a record or abstain.
    • Evaluate and govern a model in a GxP setting: recall@k, MRR and nDCG for retrieval, PR-AUC and calibration for rare labels, applicability domain, version pinning, audit trails and change control.

    Learn

    Start from the task, the label and the identifiers

    Before you pick a model, write down four things. What decision will the output inform? What is the unit of prediction: a compound, a protein target, a document passage? What is the label, and which system of record holds it? How will you split the data so that the test looks like future use? The FDA’s draft guidance on AI credibility starts in the same place. It asks the sponsor to state the question of interest and the context of use (the specific role and scope of the model) before it assesses model risk[1]. The OECD principles for QSAR models (models that predict a property from chemical structure) begin with a defined endpoint[2].

    The label is where most projects go wrong. A label such as “active” means nothing until it names an assay, a version, a unit and a cut-off. ChEMBL, the public bioactivity database, converts potency to pChEMBL, the negative log10 of the molar IC50, EC50, Ki or Kd, so 1 nM becomes 9. It computes this only for standard activity types reported in standard units[3]. Pooling a biochemical IC50 with a cell-based IC50 under one label mixes two different quantities. Store the measured value, the unit and the assay id, and derive the label in code.

    Positive examples are scarce at every stage of the funnel. Discovery projects screen 200,000 to more than 1,000,000 compounds and narrow hundreds of compounds to one or two candidates[4]. Across 9,704 clinical programmes from 2011 to 2020, the likelihood of approval from Phase I was 7.9%[5]. A table of 1,000 Phase I programmes therefore holds about 79 approvals. A model that always predicts “fails” is 92% accurate on it, which is why accuracy is the wrong headline metric.

    Joins on public identifiers were set up in the intermediate module. Here they become features: store the public id, its release and the retrieval date next to every embedding and prediction[6, 7]. Join compounds on the full Standard InChIKey. Treat a match on the first block alone as a “same skeleton” flag for review, never as a match[8].

    Embeddings for text, molecules and proteins

    An embedding is a fixed-length list of numbers (a vector) that a model produces for an input. The model is trained so that similar inputs land close together, usually measured by cosine similarity, the angle between two vectors. The point of embedding is speed. Sentence-BERT’s authors report that finding the most similar pair among 10,000 sentences takes about 65 hours if a BERT model reads every pair, and about 5 seconds if each sentence is embedded once and the vectors are compared[9]. No single text embedding model wins everywhere: the MTEB benchmark tested 33 models on 8 task types and 58 datasets and found none dominant[10]. Choose with a test set drawn from your own protocols, SOPs and reports.

    Molecules have their own embeddings. Extended-connectivity fingerprints (ECFPs) are circular fingerprints derived from a variant of the Morgan algorithm. Each atom’s neighbourhood is described, grown outward and hashed into substructure features[11]. Libraries fold the hashes into a bit vector of fixed length, by default 2048 bits in one common library. The naming trips developers: “ECFP4” gives the diameter, so it equals a Morgan radius of 2[12]. A common similarity measure between two fingerprints is the Tanimoto coefficient[13]: bits set in both, divided by bits set in either. A Tanimoto of 0.62 means nothing without the fingerprint type, radius and length, so store all three beside it.

    Proteins have learned embeddings too. ESM-2 is a protein language model trained on UniRef50 sequences. Its 650-million-parameter version has 33 layers and returns 1280 numbers for each residue; the smallest version has 6 layers and 320 numbers[14]. A per-sequence embedding is made by averaging the residue vectors, and a command-line tool writes embeddings in bulk from a FASTA file[14]. ESMFold, a structure predictor, is built on the same language model[15].

    One rule covers all three kinds. An embedding is comparable only with embeddings from the same model, version and settings. Store the model id and version with every vector. Treat a new embedding model as a change that re-embeds the whole index, never as a patch to some rows[10, 16].

    Knowledge graphs: nodes keyed on public ids

    A knowledge graph stores entities as nodes and their relations as edges, so a query can walk from a compound to its target and on to a disease. Key every node on a public identifier, never on a name: a ChEMBL id for a compound, a UniProt accession or Ensembl gene id for a target. Open Targets, the public target-disease platform, uses the Ensembl gene id as the primary identifier for human targets and draws annotation from UniProt[17]. Ensembl ids carry a version number that rises when the underlying entity changes, so key the node on the id and keep the version as a property[18]. Diseases and phenotypes come from ontologies. The Ontology Lookup Service (OLS) at EMBL-EBI is a free search engine and API for finding the ontology terms that annotate biomedical data[19]. Every edge should carry its evidence source and the release it came from. In its 2021 description, Open Targets combined evidence from 20 sources into scored target-disease associations[20]. Record the ontology release you loaded, and treat a move to a new release as a change that rebuilds the graph under change control.

    Chunking regulated documents and keeping the locator

    Retrieval works on passages, not whole documents. The Dense Passage Retrieval (DPR) authors split Wikipedia into disjoint 100-word blocks, 21,015,324 passages in total, and prepended each with its article title[21]. Protocols, clinical study reports (CSRs) and standard operating procedures (SOPs) offer a better unit than a word count: numbered sections, tables and versions. Chunk by section and paragraph. Keep the section heading with each chunk. Never cut a table in half.

    Each chunk then carries metadata, the fields you filter and cite on: document id, version, status (draft, effective, superseded), section locator, product, study and, where relevant, controlled codes. The trial master file must support document identification, version history, search and retrieval[22]. Your index inherits that duty. If a superseded protocol version sits in the index without its status, no filter can exclude it.

    Access follows the source record. Each chunk carries the access group of the record it came from, and the search filters on the user’s role inside the query. An index must never show a blinded study team a chunk from an unblinded listing. For GMP systems, Annex 11 restricts access to authorised persons[16]. For clinical-trial systems, the EMA guideline asks that only authorised people get access, with documented access levels, and that unblinded information be open only to pre-identified user roles[23]. An index that returns text to people who could not open the source record breaks that control. Case narratives and real-world records also hold health data. Under the GDPR, health data is a special category, and processing it is prohibited unless one of the listed exceptions applies[24]. Agree with your data protection lead what must be removed or pseudonymised before any text is embedded, because a vector built from a narrative is derived from that narrative.

    Retrieval also opens a security gap. In indirect prompt injection, an attacker plants instructions in data that is likely to be retrieved, and the model reads them as part of its input. NIST notes that researchers have shown such attacks stealing proprietary data or running malicious code[25]. Models may also leak or infer sensitive information about people[25]. Three habits follow. Treat retrieved text as data, never as instructions to follow. Apply the access filter before retrieval, so the generator never sees a chunk the user could not open. Put documents with planted instructions in the gold set, and pass a query only if the answer ignores them.

    Filter on codes, not on words. Adverse events are coded in MedDRA, a five-level hierarchy from System Organ Class down to Lowest Level Term, with 27 System Organ Classes in version 29.0[26]. Observational data mapped to the OMOP Common Data Model use standard concept ids from shared vocabularies[27]. Two narratives that describe the same event in different words can map to one Preferred Term. A filter on that code finds both; a keyword filter may find one. Store the dictionary version as well, because coding can change between versions[26].

    Retrieval: lexical, dense and hybrid

    Lexical retrieval scores documents by the words they share with the query. BM25, the standard lexical scorer, sums over the query terms a rarity weight (inverse document frequency) times a term-frequency function that saturates, so repeating a word stops adding score. A parameter called b sets how strongly long documents are normalised[28]. BM25 is strong where exact tokens matter: lot numbers, NCT numbers, gene symbols and SOP ids.

    Dense retrieval embeds the query and every chunk and returns the nearest vectors. DPR, a dual encoder with one encoder for questions and one for passages, beat a BM25 system by 9 to 19 points of top-20 accuracy across open-domain question sets[21]. On Natural Questions, top-20 accuracy was 59.1 for BM25 and 78.4 for DPR. On SQuAD, BM25 scored 68.8 and DPR 63.2, so lexical matching still wins on some question sets[21]. BEIR, a benchmark of 18 datasets tested zero-shot (without training on them), found BM25 a robust baseline that dense models often failed to beat[29]. Biopharma text is out of domain for most general embedding models, so test both on your own corpus.

    Hybrid retrieval runs both and merges the lists. Reciprocal rank fusion (RRF) gives each document the sum of 1/(k + rank) over the lists in which it appears, with k at its default of 60 in tools such as Elasticsearch. It uses ranks only, so the two scorers’ raw scores never have to share a scale[30, 31]. A chunk ranked 1st by BM25 and 4th by the dense retriever scores 1/61 + 1/64, about 0.0320. A chunk ranked 2nd by both scores 2/62, about 0.0323, and wins narrowly[30].

    A vector database stores the embeddings and answers nearest-neighbour queries. Most use approximate search to stay fast. HNSW, a common index type, searches a layered graph of proximity links, starting in the top layer[32]. Approximate means it can miss a true neighbour. Two design rules follow. Apply metadata filters (status, study, code) inside the search, not after it, or a post-filter can leave fewer than k results. And measure the approximate index against exact search on your own data before you rely on it[32].

    Reranking and grounded generation

    The first-stage retriever is built for speed, so its top results are noisy. A reranker reads the query and each candidate passage together and scores the pair; this design is called a cross-encoder. Nogueira and Cho’s BERT reranker topped the MS MARCO passage leaderboard at the time, a 27% relative improvement in MRR@10 over the previous best[33]. BEIR found that reranking and late-interaction models gave the best zero-shot results on average, at high computational cost[29].

    Cost is the reason to rerank only a short list. A cross-encoder runs the full network once per query-passage pair, which raises cost by orders of magnitude over comparing precomputed vectors[34]. So retrieve a candidate list with hybrid search, rerank only that list, and pass the top few chunks to the generator. Log the reranker model and version exactly as you log the embedding model[34, 16].

    Retrieval-augmented generation (RAG) joins a retriever to a text generator. Its original authors describe parametric memory (what the model learned in training) plus non-parametric memory (a dense index of documents). They note that models relying on parametric memory alone struggle to give provenance or to update their knowledge[35]. In a regulated setting, provenance is the product. Every sentence in an answer should point to a chunk. The user interface should show the document id, version and section, with a link to the record in its system of record[35, 22].

    Abstention is a feature, not a failure. When no retrieved chunk supports an answer, the system should say that no record was found and show what it searched. Test this with negative controls: questions whose answer is not in the corpus. An answer that cites a plausible wrong record is the most dangerous failure, because it looks checked. Ragas, an evaluation framework, scores RAG on separate dimensions: whether retrieval found relevant passages, whether the answer is faithful to them, and the quality of the answer[36]. Keep these scores apart; a fluent answer can be unfaithful.

    Model predictions: properties, structures, docking and free energy

    Property models predict a measured quantity from structure: potency, solubility, metabolic stability or a safety liability. ADMET stands for absorption, distribution, metabolism, excretion and toxicity. The OECD principles ask that such a model have a defined endpoint, an unambiguous algorithm, a defined domain of applicability, appropriate measures of fit, robustness and predictivity, and a mechanistic interpretation if possible[2]. The applicability domain is the chemical space in which the training data make the model’s predictions reliable. A practical check is the Tanimoto similarity of each new compound to its nearest training compound, stored with the prediction and the documented threshold.

    The split decides whether a test score means anything. A random split scatters close analogues of one series across training and test, so the model is tested on near-copies. MoleculeNet uses a scaffold split, which groups molecules by their two-dimensional core framework, as a harder test than a random split[37]. Even scaffold splits overestimate virtual-screening performance, because molecules with different scaffolds are often similar[38]. Sheridan found that training on older compounds and testing on newer ones gives an R2 closer to true prospective performance, while random selection is too optimistic[39]. Leakage is common: one survey found leakage errors in 17 fields, affecting 329 papers[40].

    Structure prediction gives coordinates plus confidence. AlphaFold’s pLDDT is a per-residue confidence on a 0 to 100 scale: 90 and above is very high, 70 to under 90 confident, 50 to under 70 low and under 50 very low. Very low regions often correspond to disorder[41]. The Predicted Aligned Error (PAE) is the expected error in the relative position of residue pairs. It tells you whether two domains are placed reliably relative to each other[42]. The AlphaFold DB record for EGFR (P00533) has a mean pLDDT of 75.94, yet 22.8% of its residues score under 50[7]. A mean hides the region you care about. Before docking into a predicted structure, check the pLDDT of the binding-site residues and the PAE between the domains that form the site.

    Docking places a ligand in a protein structure and ranks poses with a scoring function. Free energy perturbation (FEP) simulates the change in binding free energy between related ligands. Both produce predictions, not measurements. A benchmark of 1,237 ligands, by authors from the FEP+ software developer, reported a median error (RMSE) of 1.08 kcal/mol in relative binding free energy against experiment. When the same series was measured by two or more different assays, the results differed by a median RMSE of 0.85 kcal/mol[43]. The same paper equates 0.3 pKi units with 0.41 kcal/mol, so 1.08 kcal/mol is about 0.79 log units, roughly a 6-fold error in the relative affinity of two analogues[43]. Store docking scores and FEP results in a prediction table with method, version, receptor preparation and run id. Never write them into the assay results table, where a later query would treat them as measured.

    Evaluating retrieval and prediction

    Retrieval metrics need a gold set: questions, each with the record that answers it, its locator and a named reviewer. Recall@k is the share of questions whose gold record appears in the top k. Mean reciprocal rank (MRR) averages 1 divided by the rank of the first correct record, so rank 1 scores 1, rank 3 scores 0.33 and a miss scores 0. Benchmarks report it at a cut-off, such as MRR@10[33]. nDCG (normalised discounted cumulative gain) uses graded relevance, such as highly, partly or not relevant, and rewards placing the most relevant records first, relative to the ideal ranking[44]. Report k, the index version and every model version with each number.

    Prediction metrics must respect the base rate. The ROC curve plots true-positive rate against false-positive rate and does not change with class balance. The precision-recall curve does change, which makes it the more informative plot for imbalanced data[45]. A random classifier has an AUROC of 0.5 at any base rate, but its precision equals the positive rate: 0.01 when 1% of compounds are positive[45]. MoleculeNet scores several of its datasets by PRC-AUC for this reason[37]. Report PR-AUC next to the base rate, and against a simple baseline such as nearest-neighbour similarity.

    A probability should also mean what it says. A model is calibrated when, of the compounds it scores 0.8, about 80% turn out positive. Modern neural networks are often poorly calibrated. Temperature scaling, a one-parameter correction fitted on held-out data, worked on most of the image and text datasets the authors tested[46]. Test it on your own held-out compounds. Calibration matters whenever a chemist reads the score as a probability when choosing which compounds to make.

    Human review closes the loop. Subject-matter experts write and grade the gold set, and their judgements are attributable records. The EMA reflection paper treats the hold-out test set as something used once, and expects a new independent test set after further development. It strongly encourages splitting off the test data early, before normalisation[47]. Freeze the test set, version it and keep it out of every tuning step.

    GxP: context of use, credibility, freezing and change control

    GxP is shorthand for the good practice rules (laboratory, clinical, manufacturing) that govern regulated records. The FDA draft guidance of January 2025, not for implementation, sets out a seven-step risk-based credibility framework. The steps are: define the question, define the context of use, assess model risk, plan, execute, document results and deviations, and decide adequacy[1]. Model risk combines model influence (how much the output drives the decision) with decision consequence. The draft excludes drug discovery uses and operational efficiencies that do not affect patient safety, drug quality or study reliability[1]. A property model that helps choose which compounds to make is a discovery use; the same kind of model producing evidence for a regulatory decision would need the framework.

    The EMA reflection paper, adopted in September 2024, expects that in pivotal trials the models and data pre-processing pipelines are frozen and documented before unblinding. It does not accept incremental learning there[47]. In January 2026 the EMA and FDA jointly published ten guiding principles of good AI practice in drug development. They are high-level principles meant to inform future guidance and standards; they include a clear context of use and traceable data governance and documentation[48]. For a developer, freezing is concrete: a model artefact with a hash, a pinned embedding model, a pinned index version, a pinned dictionary version, and a test record that names all of them.

    Part 11 and Annex 11 turn this into code. 21 CFR 11.10(e) requires secure, computer-generated, time-stamped audit trails that record operator entries and actions that create, modify or delete electronic records, without obscuring earlier values[49]. FDA’s Part 11 guidance applies the rule to records required by predicate rules or relied on for regulated activities, so decide and document which of your outputs are such records[50]. Annex 11 asks for validation scaled by documented risk and for change control records. It asks firms to consider, based on a risk assessment, a system-generated audit trail of GMP-relevant changes[16]. The MHRA expects audit trails to be switched on, not switchable by users, and no shared logins for GxP data[51].

    In practice, a new MedDRA version, a new embedding model, a rebuilt index or a retrained property model is a change request. The request names the risk, the tests to rerun (the frozen retrieval gold set, the prediction hold-out set and the negative controls) and the approver. GAMP 5, the industry guide for computerised systems, frames this as a risk-based approach that keeps systems fit for intended use[52]. Your automated tests, stored with their inputs, versions and results, are the validation evidence[16].

In the messy table, an entry name sits in the accession column and a pLDDT is written as an accuracy[data].

    1. Filter the index. A user asks “what is the primary analysis in PROT-001?”. Your filter keeps chunks with status effective or final. Which PROT-001 chunks in the good table survive, and which messy rows would break the answer, its citation or its access control?[data]
    Answer

    In the good table, CHK-000101 and CHK-000102 (PROT-001 v3, effective) survive; CHK-000088 (v2, superseded) is dropped[data]. In the messy table, CHK-000088 has a blank status, so the filter cannot drop it and the answer can quote the old protocol. CHK-000102 has no locator, so the answer cannot cite a paragraph. The SOP chunk of 1,850 words is about 18.5 times the 100-word passage size DPR used, so one vector must stand for many topics[data][21]. The cut table and the chunk embedded with EMB-TXT v3.0 are two more defects; the fix for the second is to re-embed the whole index under change control. Messy row 1, the unblinded listing CHK-000391, has no access group, so the search cannot hide it from a blinded user[data].

    1. Score the acceptance test. Using the good table, compute recall@5 and MRR over the answerable queries, then judge the negative control.
    Answer

    Q-005 is the negative control, so 5 queries are answerable: gold ranks 1, 3, not retrieved, 2 and 1[data]. Recall@5 = 4/5 = 0.80. MRR = (1 + 1/3 + 0 + 1/2 + 1) / 5 = 2.833 / 5 = 0.567. Q-005 passes because the system abstained. In the messy table, Q-005 returned CASE-2024-0199 and was still marked “pass”; that is a failure and counts toward the hallucination rate[data]. Q-004 shows PROT-001 v2 at rank 1, a sign that the status filter from exercise 1 is missing.

    1. Fuse two rankings. For a query about deviation handling, BM25 returns CHK-000245, CHK-000246, CHK-000390 and the dense retriever returns CHK-000246, CHK-000088, CHK-000245. Compute RRF scores with k = 60, then apply the status filter[data].
    Answer

    CHK-000246: 1/62 + 1/61 = 0.01613 + 0.01639 = 0.03252. CHK-000245: 1/61 + 1/63 = 0.01639 + 0.01587 = 0.03227. CHK-000088: 1/62 = 0.01613. CHK-000390: 1/63 = 0.01587[30]. Fused order: 246, 245, 088, 390. CHK-000088 is a superseded protocol chunk, so the status filter removes it before reranking[data]. Filter inside the search, or the top k shrinks after the fact.

    1. Read a classifier on a rare label. Using the good prediction table, give the base rate, precision and recall at a 0.5 threshold, and the AUROC by counting pairs. Then name the messy rows that make the score untrustworthy.
    Answer

    Labels: 2 positives in 6 rows, a base rate of 0.33[data]. At 0.5 the model flags CPD-0201 (0.82, positive) and CPD-0215 (0.61, negative): precision 1/2 = 0.50, recall 1/2 = 0.50[data]. AUROC: 2 positives times 4 negatives gives 8 pairs. CPD-0201 (0.82) beats all 4 negatives; CPD-0207 (0.35) beats 0.20 and 0.12 but loses to 0.61 and 0.48. That is 6 of 8, an AUROC of 0.75[data]. A random model scores 0.5 on AUROC but only about 0.33 precision here, so report both[45]. Report in-domain and out-of-domain rows separately: here 4 rows are in domain (2 positives, 2 negatives, AUROC 3 of 4 pairs = 0.75) and 2 are out, both negative, so no AUROC can be computed for them[data][2]. Six rows are far too few for a decision. In the messy table, row 1 used a random split with a 0.93 neighbour in training, row 5 was flagged in-domain at 0.31, and row 6 was registered before the cut-off[data][39].

    1. Decide which predicted structure to use. For each target, estimate how many residues have pLDDT under 50. Which model has the largest very-high share, and what do you still check before docking? What do you store from the API call?[data]
    Answer

    Residues under 50 = fraction times residues modelled[data]. EGFR 0.228 x 1210 = about 276. TP53 0.298 x 393 = about 117. KRAS 0.021 x 189 = about 4. BRCA1 0.804 x 1863 = about 1498. AR 0.582 x 920 = about 535. KRAS has the largest very-high share: 77.8% of its residues score 90 or above (about 147 of 189), and only 2.1% score under 50[data]. TP53 is also more than half very high (52.7%) but has 29.8% under 50, so its mean of 75.06 hides two very different regions[data]. EGFR has a similar mean, 75.94, with 47.4% very high and 22.8% under 50[data]. In every case you check pLDDT at the binding-site residues, and PAE between the domains that form the site, before docking[41]. Join TGT-0003 to P01116, call /api/prediction/P01116, and store the model id AF-P01116-F1, version 6, the band fractions, the PAE file link and the retrieval date[data][53].

    1. Translate an FEP error into potency. A team says FEP predicts a new analogue is 3-fold more potent. Is that difference larger than the method’s typical error?
    Answer

    From 0.3 pKi units = 0.41 kcal/mol, one log unit is 0.41 / 0.3 = 1.37 kcal/mol[43]. The benchmark median RMSE of 1.08 kcal/mol is 1.08 / 1.37 = 0.79 log units, and 10 to the power 0.79 is about 6.2-fold. Different assays of the same series differ by 0.85 kcal/mol, or 0.62 log units, about 4.2-fold[43]. A predicted 3-fold gain is inside both, so treat it as a hypothesis to test by assay, and store it in the prediction table, not with measured results.

    1. A model scores AUROC 0.90 on compounds where 1% are positive. What must the team also report? a) Accuracy b) Training loss curve c) PR-AUC with the 1% base rate d) The number of layers
    2. Of the compounds a model scored 0.8, 40% turned out positive. The model is: a) calibrated b) over-confident c) under-confident d) unbiased
    3. Dense retrieval misses queries that contain lot numbers and NCT numbers. What is the first fix to test? a) Hybrid search with BM25, fused by reciprocal rank b) A larger generator c) Removing the metadata filters d) Raising the sampling temperature
    4. An AlphaFold DB model has a mean pLDDT of 75. What do you check before docking into it? a) Nothing, 75 is confident b) The crystallographic resolution c) The R-factor d) pLDDT at the binding-site residues and PAE between the domains
    5. A model supports the primary analysis of a pivotal trial. What does the EMA reflection paper expect? a) Weekly retraining on new trial data b) Models and pipelines frozen and documented before unblinding c) Tuning on the test set d) Incremental learning during the trial

    Answer key: 1-c, 2-b, 3-a, 4-d, 5-b
