Built with Claude: Life Sciences hackathon · 7 – 13 Jul 2026 · team lead, team of 3

FACET

One drug name in, four dossiers out, one each for a medicinal chemist, a pathologist, a molecular biologist and a computational biologist. The design rule is that retrieved values must appear unchanged.

Code ↗Video ↗

The hackathon ran from 7 to 13 July 2026, organised by Anthropic, Gladstone and Cerebral Valley. We were a team of three: Balaji, Kavvuri Raghavendra and I. I led the team. We built FACET, a pipeline that takes a drug name and writes four reference dossiers, one for each discipline, from data it retrieves for that discipline.

The aim

General AI tools give the same answer to everyone, whatever their role. A medicinal chemist asking about imatinib and its target ABL1 needs potency values and co-crystal structures. A pathologist needs the resistance mutations and their clinical significance. FACET sends one query through four disciplines: medicinal chemist, pathologist, molecular biologist and computational biologist. The discipline decides which databases are queried and how the answer is structured.

What we built

The pipeline has three steps.

  • Resolve. From a plain drug name, and a target if one is given, the resolver finds the identifiers. These are ChEMBL ids for the drug and the target, the PubChem compound id, UniProt, Ensembl, the best co-crystal structure in the PDB and the code of the bound ligand. If no target is given, it is inferred from the mechanism recorded in ChEMBL.
  • Retrieve. Each discipline has its own list of connectors to open data sources. There are 15 connectors: PubChem, ChEMBL, RDKit descriptors, PDB, ADMET, Open Targets, UniProt, Protein Atlas, ClinVar, PubMed, AlphaFold, STRING, GTEx, InterPro and Reactome.
  • Write. A language model writes the dossier from three inputs: the discipline’s definition file, a shared response template and the retrieved data.

Erlotinib and its target EGFR are the worked example. Nothing about them is hardcoded; the same call works for imatinib and vemurafenib.

Design rules

  • No drug facts in the discipline files. Each holds only its connector list, its reasoning rules and a section outline. Erlotinib appears there only as a labelled example.
  • Retrieved values appear as retrieved. A value from a connector or from RDKit must appear unchanged in the dossier. Established pharmacology may be added, but it must be labelled, and it must not contradict retrieved data or invent it.
  • Inputs come from the resolver. Structural and potency inputs pass from the resolver to the connectors, not from values written into a discipline file.
  • A missing field does not stop the run. If the resolver finds no co-crystal structure, for example, the connectors handle the gap.

The regression test

One fixed query is the regression test: “what are the molecular properties of erlotinib”. It is run for all four disciplines. Each output is compared with a ground-truth reference file for that discipline, and an automated test checks for expected markers in the output. The repository reports no pass rate or other result for it.

The erlotinib ground-truth set, the discipline files, the connector configuration and the marker fixtures were generated with help from an agentic AI platform.

What the repository reports

These figures are from the repository’s architecture document.

  • Tests. 12 connector tests against the live data sources; 10 tests of query parsing, identifier resolution and role detection; 9 tests of the user interface; and 18 end-to-end tests. The 18 are four disciplines with three questions each, two comparisons and four role-detection cases.
  • Model calls. A query shown in all four disciplines takes about five model calls: one to parse the query and one per discipline to write.
  • Time. Resolving identifiers takes about 2 to 4 seconds and retrieval about 5 to 10 seconds. The written answer then streams over about 15 to 30 seconds. These are approximate.
